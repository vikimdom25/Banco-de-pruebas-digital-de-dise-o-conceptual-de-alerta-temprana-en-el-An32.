## 2026-02-14 - [Scikit-learn Scaler Overhead in High-Frequency Loops]
**Learning:** In high-frequency telemetry loops (such as the 50Hz telemetry queue loop in `ModelWorker._escalar`), calling `.transform()` on scikit-learn StandardScaler or MinMaxScaler instances introduces massive overhead (up to ~80x slower than raw mathematics). This is due to scikit-learn's extensive input checks, dimensions validations, and feature name checks performed on every single row-by-row call. Additionally, it triggers noisy `UserWarning`s when the inputs lack explicit feature names.
**Action:** Extract and cache the scaler attributes (`mean_`, `scale_`, `min_`) during model/worker initialization, and perform the algebraic calculations directly using NumPy or basic scalar arithmetic in the loop. This retains mathematical equivalence while achieving a tremendous speedup (~80x).
